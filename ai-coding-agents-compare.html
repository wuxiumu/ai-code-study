01

先统一认知：编码 Agent 到底在做什么

编码 Agent 不是“更聪明的代码补全”，而是一个能读仓库、能改文件、能跑命令、能自我纠错的终端助手。你给它一个自然语言任务，它会自己拆解步骤、调用工具、观察结果、继续迭代，直到完成。

它和传统 IDE 插件（如 Copilot）的核心区别是主动性：Copilot 等你敲代码时给建议；Agent 会主动执行 git diff、pytest、pip install 等命令，并基于反馈继续改。你更像一个项目经理，而不是一个打字员。

核心能力
读目录、读文件、写文件、执行命令、调用外部工具
关键循环
思考 → 行动 → 观察 → 再思考（ReAct / Agent Loop）
安全机制
权限模式、审批确认、沙箱执行、只读模式
选型关键
模型质量 × 上下文窗口 × 工具链 × 价格 × 隐私/合规

02

五款工具一句话定位

  • A

    Claude Code

    Anthropic 官方出品，Claude 模型加持，代码理解强、上下文长、文档编辑稳，适合中大型项目与复杂重构。

  • B

    Codex

    OpenAI 的编码 Agent，与 ChatGPT 生态打通，云端任务与本地 CLI 并行，适合已在使用 OpenAI 服务的团队。

  • C

    Kimi Code

    国产终端编码 Agent，中文体验好、国内访问稳、长文本是强项，适合中文开发者与国内企业场景。

  • D

    OpenCode

    开源、模型无关，可自托管、可换任意模型，适合想掌控数据、想自定义 Agent 行为的技术团队。

  • E

    Pi Agent

    极简内核 + 强扩展设计，小到能读完源码，适合想深度定制、学习 Agent 架构的开发者。

04

按场景推荐：别只看参数，看你要干什么

场景一：日常写代码、改 Bug、跑测试

这是最常见的需求。你不需要最强的模型，但需要稳定、响应快、不会乱改。Claude Code 和 Kimi Code 在这类任务上都很稳；如果你已经买了 ChatGPT Plus，Codex 也能无缝接入。

推荐组合
个人日常开发    → Claude Code 或 Kimi Code
国内网络环境    → Kimi Code
已用 OpenAI     → Codex
预算敏感        → OpenCode + 本地/低价模型

场景二：大型代码库重构

大仓需要 Agent 能读很多文件、记住跨文件关系、一次性改多处。Claude Code 的长上下文和文件编辑能力在这里优势明显；Kimi Code 的长文本能力也能覆盖大仓。

场景三：企业 / 私有代码

如果代码不能出内网，闭源云方案直接出局。OpenCode 或 Pi 配合本地模型（Ollama / vLLM）是合规路径。OpenCode 的模型无关和可扩展性更适合企业定制。

场景四：学习 Agent 原理

想搞清楚 Agent 循环、工具调用、记忆系统怎么实现？Pi 的极简内核最适合当教材；读完源码再去看 Claude Code / OpenCode 的高级抽象会轻松很多。

场景五：教学、写教程、做 demo

需要可复现、可解释的步骤。Claude Code 的“思考过程”展示和 Kimi Code 的中文输出都比较适合录屏；OpenCode 则适合展示“自定义 Agent”的可能性。

05

每款深入：适合谁，不适合谁

Claude Code

优势是代码理解深度和长上下文。处理复杂需求、跨文件重构、写测试用例时，输出质量通常很高。权限模式成熟，可以让它只读、审批后执行、或全权限。

劣势是依赖 Anthropic 服务，国内访问需要网络条件；价格按模型 token 计费，重度使用成本不低。

适合：海外开发者、中大型项目、愿意为好模型付费的团队。

Codex

OpenAI 把 Codex 做成了云端任务 + 本地 CLI的双形态。你可以把一整个需求丢给云端让它慢慢跑，也能在终端里即时交互。和 ChatGPT、GitHub Copilot 账号体系打通是最大便利。

劣势是黑盒程度高，沙箱与审批机制有时会让简单任务多一步确认。

适合：OpenAI 生态用户、需要云端长任务、团队协作。

Kimi Code

长文本是 Kimi 的招牌，放到编码 Agent 里就是能一次性吞下更多上下文，对大文件、多文件任务友好。中文指令理解自然，国内网络无压力。

劣势是生态还在快速迭代中，部分高级功能（如复杂审批流、沙箱）可能不如海外成熟产品丰富。

适合：中文开发者、国内公司、长文档/大仓场景。

OpenCode

最大卖点是开源 + 模型无关。你可以接 OpenAI、Claude、Kimi、本地 Llama/Qwen/DeepSeek，甚至自己微调的模型。AGENTS.md 项目约定和 MCP 扩展让它在企业场景很有想象空间。

劣势是需要自己配置模型和权限，文档和社区支持相对年轻，出问题得多看源码。

适合：技术团队、私有化部署、想自定义 Agent 行为的用户。

Pi Agent

Pi 的哲学是小内核、大扩展。核心代码量不大，但插件/技能/模板/主题都能扩展。它更像一个“可读的 Agent 框架”，而不是一个开箱即用的大而全产品。

劣势是功能不如商业产品完备，需要你自己搭积木。

适合：想学习 Agent 架构、喜欢自己动手的开发者。

安装上手门槛：从 0 到第一次对话

五款工具的安装都不算复杂，但依赖环境略有不同。下面是最简路径：

工具最简安装
Claude Codenpm install -g @anthropic-ai/claude-code，然后 claude 登录 Anthropic 账号
Codexnpm install -g @openai/codex，配置 OpenAI API Key
Kimi Code按官方 CLI 指引安装，登录 Kimi 账号
OpenCode克隆仓库 / 安装包，配置模型 provider 与 API Key
Pi克隆仓库，安装依赖，配置模型后即可 pi
通用提醒：所有工具都不要把 API Key 写进代码，统一放环境变量；企业内网使用前确认合规。

07

常见误区：选型时别踩这些坑

  • 误区 1：参数最强的就是最适合自己的。大模型能力强，但响应慢、价格高。日常改 Bug 用中等模型反而更划算。
  • 误区 2：开源等于免费。开源工具省的是授权费，但模型调用、服务器、维护人力都要算成本。
  • 误区 3：一个工具走天下。不同任务可以换不同工具；比如用 Claude Code 做复杂重构，用 Kimi Code 快速中文问答。
  • 误区 4：给了全权限就不管了。再强的 Agent 也会幻觉、也会误删文件。审批模式和 git 提交是底线。
  • 误区 5：只看首屏价格。编码 Agent 的账单按 token 走，重度使用下价格差异会放大，先估算自己的调用量。

08

选型决策树：三步定案

decision-tree.txt
1. 代码能不能出内网 / 能不能用海外服务？
   是 → 继续看 2
   否 → OpenCode 或 Pi + 本地模型

2. 更看重中文体验还是海外生态？
   中文 / 国内 → Kimi Code
   海外 / 已有 OpenAI/Anthropic 账号 → 继续看 3

3. 主要做复杂重构、大仓，还是日常任务？
   复杂重构 / 大仓 → Claude Code
   日常 / 云端长任务 / OpenAI 生态 → Codex

4. 想学习 Agent 原理或深度定制？
   → Pi 或 OpenCode
这张决策树不是唯一答案。最好的方式是：按你的真实项目跑一遍同样的任务，看哪个 Agent 的完成度和你的满意度最高。
