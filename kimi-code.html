01

先看清这台机器：装了桌面版，但还没装 CLI

Kimi Code 有两个入口，共用同一套账号与配置目录。你机器上是桌面版在跑，终端里的 kimi 命令还没出现在 PATH 里——所以现在敲 kimi 会是 command not found。

为什么还要 CLI：桌面版是图形界面，CLI 让你把 Agent 放进仓库、放进脚本、放进 CI 前的本地批量任务里——批量改名、跑测试、读日志、串脚本，这些在终端里更顺手。数据都在 ~/.kimi-code，两边登录态互不冲突。

02

安装：三个方式选一个

推荐官方脚本，它下载独立二进制、校验 checksum，不需要 Node.js。你机器上 Homebrew 和 nvm 都在，另外两条路也能走。

Terminal
# macOS / Linux：装二进制 + 校验，无需 Node
curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash

# 装完重开一个终端，确认它进 PATH 了
kimi --version
脚本会把 kimi 放进 PATH。如果新终端仍找不到，见第 08 节的 PATH 处理。
Terminal
# 你机器上 Homebrew 已可用
brew install kimi-code

kimi --version
brew upgrade kimi-code   # 以后升级走这条
注意：kimi-code 是 Kimi Code CLI 的公式名；kimi-cli 是老一代 Python 版的名字，两者不是同一个包。
Terminal
# 需要 Node ≥ 22.19；本机系统默认 node 只有 v12，先切版本
nvm use 22.22.0
node --version

npm install -g @moonshot-ai/kimi-code

# pnpm 也行
pnpm add -g @moonshot-ai/kimi-code
npm 全局安装的 bin 目录必须在 PATH 里，否则同样会 command not found。
装到哪了：官方脚本装进你的用户 bin 目录（安装器最后会打印具体路径），Homebrew 装到 /opt/homebrew/bin。不管哪种，装完先 重开终端再验证，比在旧窗口里折腾 PATH 省事。

03

登录：设备码，或者 API Key

首次启动必须给 CLI 一个模型来源。最省事的是 OAuth 设备码——任何设备扫码/输码授权，不用手抄密钥。

Terminal · 两种登录入口
# 方式一：不开 TUI，直接在命令行走 OAuth
kimi login

# 方式二：已经进了交互界面，用斜杠命令
> /login

/login 会弹出平台选择：

  • Kimi Code（OAuth）：给出链接与验证码，在任意设备上登录后填回验证码即完成授权。
  • Kimi Platform API 密钥：贴入 platform.kimi.com / platform.kimi.ai 签发的密钥。
Terminal · 检查与登出
# 确认配置和凭证都没问题
kimi doctor

# 退出登录，清掉当前凭证
> /logout

# 查看当前版本 / 模型 / 目录 / 权限模式
> /status

接别家模型

想用 Anthropic、OpenAI、Google 等供应商，不走 /login，直接改配置文件：~/.kimi-code/config.toml。你机器上这份文件已存在（桌面版建的），里面 default_model、providers、models 三段就是关键；改完在会话里 /reload 生效。

04

第一次对话：三个参数解决 90% 场景

Terminal
# 进仓库再启动，上下文边界就是当前目录
cd ~/your-project
kimi

# 只要一条结果，不想要交互界面
kimi -p "帮我梳理这个项目的目录结构，指出哪些是入口文件"

# 接着上一次的会话干（同目录）
kimi -c          # 等价于 --continue
kimi --session   # 不给 id 就弹出会话选择器
  • 01

    进目录再启动

    Agent 的能力边界跟着工作目录走。在仓库根启动，它读的就是这个仓库；在其他目录启动，它看不到你的代码。

  • 02

    先用只读操作试水

    「看一下目录结构」「解释这个模块」这类只读请求默认自动执行不打断你；改文件、跑命令才会弹审批。

  • 03

    任务要具体

    「在 src/utils 加一个 toKebabCase 函数并补单测」比「优化一下代码」有用得多——它会规划步骤、改文件、跑测试，每一步都告诉你干了什么。

不知道能做什么就先按 /help：命令与快捷键面板都在里面，Esc 关掉。退出用 /exit，输入框为空时连按两次 Ctrl-C 或按 Ctrl-D 也可以。

05

命令速查：装完就靠这张表

下面这块表格能搜。忘了某个命令叫什么，直接搜 session、压缩、审批 之类的词。

命令作用
kimi在当前目录开一个交互会话
kimi -c / --continue恢复本目录最近一次会话
kimi -S <id>按会话 id 恢复；不给 id 就开会话选择器
kimi -p "<提示词>"单次执行，不进 TUI
kimi -m <model>指定模型启动，如 kimi-code/kimi-for-coding
kimi --plan以 Plan 模式开新会话（先规划再动手）
kimi -y / --yolo常规操作自动批准，风险操作仍询问
kimi --auto全部自动，不提问。只在可信目录用
--output-format stream-json输出 JSONL 事件，给脚本/管道用，仅配 -p
--skills-dir <dir>从指定目录加载 Skills，替换默认扫描
命令作用
/help命令与快捷键面板（别名 /h、/?）
/loginOAuth 或 API Key 登录
/init分析代码库，生成或刷新 AGENTS.md
/plan on | off进入 / 退出 Plan 模式
/new开新会话，清空当前上下文（别名 /clear）
/sessions浏览历史会话并切过去（别名 /resume）
/compact压缩上下文，释放 token；可附一句「要保留什么」
/fork复制当前会话为独立分支，人还留在原会话
/undo [n]从上下文里撤掉最近 n 条提示
/model切换本次会话的模型
/effort切思考强度：关 / 低 / 高 / 最高
/tasks后台任务列表
/usagetoken 用量、上下文占用、配额
/status版本、模型、工作目录、权限模式
/permission选权限模式（询问 / 按需 / 全自动）
/mcpMCP 服务器及连接状态
/mcp-config配置 MCP，含 OAuth 登录
/skill:<name>调用已安装的 Skill
/export-md把当前会话导出成 Markdown（别名 /export）
/reload重载会话，让 config.toml / tui.toml 生效
/exit退出（别名 /quit、/q）
按键作用
Enter提交输入
Shift-Enter / Ctrl-J输入框内换行
Shift-Tab切换 Plan 模式
Ctrl-S输出过程中插入消息，不必等它说完
Esc打断流式输出 / 关弹窗
Ctrl-C打断输出；空输入框时连按两次退出
Ctrl-D输入框为空时退出
Ctrl-O展开 / 收起工具输出
Ctrl-B把正在跑的 shell 命令转成后台任务
Ctrl-V从剪贴板粘图片或视频（Windows 用 Alt-V）
Ctrl-G用外部编辑器写长输入
Ctrl-E审批面板里展开 diff
1 – 9审批面板里按数字选选项
子命令作用
kimi login不开 TUI 直接走 OAuth 设备码登录
kimi doctor校验 config.toml 与 tui.toml
kimi acp作为 Agent Client Protocol 服务器跑，供 IDE 接入
kimi web本地 Web UI + REST / WebSocket API
kimi rc远程控制打开 Web UI（别名 kimi remote）
kimi session list列出会话，脚本里好取 id
kimi export [id]把会话打包成 ZIP
kimi upgrade检查新版本并给出升级选项

没有匹配的命令。换个词试试，比如「会话」「压缩」「审批」。

06

日常流程：一次到位的新仓库开场

新仓库第一次进去，按这四步走，后面每次能省掉大量解释成本。

Terminal · 新仓库开场
cd ~/your-project
kimi

> /login      # 首次：登录
> /init       # 生成 AGENTS.md，把项目约定写进去
> /status     # 核对模型、目录、权限模式
> /help       # 不确定就翻这里

拆大任务：先规划再动手

Terminal · Plan 模式
> /plan on
> 把认证模块换成新的 token 格式，同时更新所有调用方

# 它会先探索代码、给出改动计划，你批准后才动文件
> /plan off    # 回到直接执行

涉及几十个文件的重构，别在普通模式下一句话开干——Plan 模式会先给你看清单，改错的成本低得多。

长任务与长会话

Terminal · 后台与上下文
> 跑一遍测试套件，跑完告诉我结果     # 它会转成后台任务
> /tasks                            # 看后台任务列表和输出
> /compact                          # 上下文变长后压缩，留住结论
> /export-md                        # 把整段会话导出成 Markdown 存档

07

权限：三档，别一上来就全自动

只读工具（Read / Grep / Glob / 读图 / 抓网页）默认自动放行；写文件、跑 shell、停任务、建计划默认要你点头。三档的边界很清楚：

默认（询问）
每次写文件、跑命令都弹审批。陌生仓库、生产数据就用这档。
/yolo、--yolo
常规操作自动批，风险操作仍问你。自己常年在维护的仓库适合。
/auto、--auto
全自动不问。只在完全信任、且有版本控制的目录里用。
一条硬线：凡是 --yolo / /auto，都等于把「能不能改」的判断权交出去。仓库有未提交改动、或脚本会碰线上环境时，先 git status 看一眼，再决定用哪档。

08

排障与维护：四个最常见的坑

坑一：kimi: command not found

先看装到哪了，再看 PATH 里有没有。你机器上 PATH 由 zsh 配置，新装的可执行文件往往要重开终端才生效。

Terminal · 定位与修 PATH
which kimi
echo $PATH | tr ':' '\n' | grep -E 'homebrew|\.local/bin'

# Homebrew 装的：确认 /opt/homebrew/bin 在 PATH 里
# 脚本装的：确认安装器最后打印的 bin 目录在 PATH 里
# npm 装的：ln -s 到 ~/.local/bin，或把 npm bin 目录塞进 PATH

# 临时验证，不改配置
/opt/homebrew/bin/kimi --version

坑二：登录后模型报错 / 配置写坏

Terminal
kimi doctor              # 校验 config.toml + tui.toml
open ~/.kimi-code         # 配置、凭证、日志都在这里
tail -n 50 ~/.kimi-code/logs/kimi-code.log

这个目录和 Kimi 桌面版共用。桌面版能正常用，说明凭证是好的——问题通常出在 CLI 读的某个字段（比如 providers 段）跟当前版本不匹配。

坑三：上下文越来越慢、答得越来越飘

长会话别硬扛：/compact 压缩，需要保留的重点直接写一句在命令后面（/compact 保留架构结论和未完成的 todo）。真接不上就 /new 重开，或者 /export-md 存档后重开。

坑四：升级与卸载

Terminal
# 查更新（脚本装、brew 装都认）
kimi upgrade

# brew 卸载
brew uninstall kimi-code

# npm 卸载
npm uninstall -g @moonshot-ai/kimi-code
